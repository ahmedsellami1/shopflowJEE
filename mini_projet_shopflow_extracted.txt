1. Contexte et Objectifs
Dans ce projet, vous devez concevoir et développer ShopFlow, une plateforme e - commerce
complète permettant à des vendeurs de publier leurs produits et à des clients d'effectuer des
achats en ligne. Ce sujet couvre l'ensemble de la chaîne de valeur d'une bo utique numérique
moderne : catalogue produits, panier, commandes, paiement simulé et gestion des stocks.
1.1 Présentation du système
ShopFlow est une marketplace B2C (Business to Consumer) comportant trois profils utilisateurs :
 ADMIN : gestion globale de la plateforme, des utilisateurs et des catégories
 SELLER (Vendeur) : gestion de sa boutique, de ses produits et de ses commandes reçues
 CUSTOMER (Client) : navigation dans le catalogue, gestion du panier, passage de
commandes
1.2 Objectifs pédagogiques
 C oncevoir une API REST complète avec Spring Boot 3 et Jakarta EE
 Modéliser des relations JPA complexes (ManyToMany, héritage, composition)
 Implémenter des règles métier réelles : stock, statut de commande, remises
 Gérer l'authentification et les autorisatio ns par rôle (Spring Security + JWT)
 Construire une interface utilisateur dynamique consommant l'API
 Produire une documentation Swagger/OpenAPI exploitable
2. Spécifications Fonctionnelles
2.1 Gestion du Catalogue Produits
 Ajouter, modifier, désactiver un produit (SELLER/ADMIN)
 Associer un produit à une ou plusieurs catégories
 Gérer les variantes d'un produit : taille, couleur, avec stock individuel par variante
 Uploader des images (URL distante ou champ texte simulant l'upload)
 Recherche plein texte : nom, description, catégorie, prix min/max
 Trier par prix, popularité, nouveautés ; pagination obligatoire
 Afficher les produits en promotion (prix barré + pourcentage de remise)
2.2 Gestion des Utilisateurs
 Inscription client avec validation (email unique, mot de passe fort)
 Authentification par JWT (access token + refresh token)
 Gestion du profil : adresses de livraison multiples, historique de commandes
 Inscription vendeur avec informations boutique (nom, l ogo, description)
 Activation / désactivation de compte (ADMIN)
 Réinitialisation de mot de passe par token

2.3 Panier d'Achat
 Ajouter / retirer des produits (ou variantes) dans le panier
 Modifier les quantités avec vérification du stock disponible en temps réel
 Appliquer un code promo (remise fixe ou pourcentage)
 Calculer le sous - total, frais de livraison et total TTC
 Sauvegarder le panier en base (persistant après déconnexion)
2.4 Gestion des Commandes
 Passer une commande depuis le panier (vérification st ock finale)
 Choisir une adresse de livraison parmi les adresses sauvegardées
 Simuler le paiement : PENDING - > PAID - > PROCESSING - > SHIPPED - > DELIVERED
 Annuler une commande (seulement si statut PENDING ou PAID)
 Remboursement simulé en cas d'annulation
 Génération d'un numéro de commande unique (ex : ORD - 2024 - XXXXX)
 Notification de changement de statut (réponse API ou flag isNew)
2.5 Avis & Notation
 Laisser un avis (note 1 - 5 + commentaire) uniquement sur un produit acheté
 Calcul de la note moyenne automatique
 Modération des avis (ADMIN)
2.6 Tableau de Bord
 ADMIN : chiffre d'affaires global, top produits, top vendeurs, commandes récentes
 SELLER : revenus, commandes en attente, alertes de stock faible
 CUSTOMER : mes commande s en cours, mes derniers avis

3.2 Architecture en couches ² obligatoire
 Controller : expose les endpoints REST, valide les entrées (@Valid), retourne les DTOs et
codes HTTP
 Service : contient la logique métier, les règles de gestion, les transactions (@Transactional)
 Repository : interfaces Spring Data JPA, requêtes JPQL ou dé rivées, Specifications pour
les filtres complexes
 Entity : entités JPA annotées (Jakarta Persistence), relations, contraintes, lifecycle hooks
 DTO : Request / Response séparés des entités ² jamais d'entité exposée directement
 Exception : classes d'exceptio n métier custom + @ControllerAdvice globalisant la gestion
des erreurs
 Mapper : conversion Entity < - > DTO (MapStruct ou manuel)
3.3 Modèle de données (entités minimales)
 User : id, email, motDePasse, prenom, nom, role (ADMIN/SELLER/CUSTOMER), actif,
dateC reation
 SellerProfile : id, user (1 - 1), nomBoutique, description, logo, note
 Address : id, user, rue, ville, codePostal, pays, principal (boolean)
 Category : id, nom, description, parent (auto - référence pour sous - catégories)
 Product : id, seller, nom, description, prix, prixPromo, stock, actif, dateCreation, categories
(M - M), images
 ProductVariant : id, product, attribut (ex: Taille), valeur (ex: M), stockSupplémentaire,
prixDelta
 Cart : id, customer (1 - 1), lignes (1 - M), dateM odification
 CartItem : id, cart, product, variant (nullable), quantite
 Order : id, customer, statut (enum), numeroCommande, adresseLivraison, sousTotal,
fraisLivraison, totalTTC, dateCommande, lignes
 OrderItem : id, order, product, variant, quantite, prixU nitaire
 Coupon : id, code, type (PERCENT/FIXED), valeur, dateExpiration, usagesMax,
usagesActuels, actif
 Review : id, customer, product, note (1 - 5), commentaire, dateCreation, approuve
Les relations doivent être correctement configurées : cascade, orphanRe moval, FetchType (LAZY
par défaut, EAGER avec justification).
